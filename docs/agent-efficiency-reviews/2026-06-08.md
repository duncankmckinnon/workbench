### `thirdeye-review-preflight`

- **Trigger:** "efficiency review", "thirdeye review", "session population scan", or any workflow
  that depends on historical thirdeye data.
- **Workflow outline:**
  1. Verify `thirdeye` is installed or install `thrdi` into the user-local environment.
  2. Resolve `THIRDEYE_HOME` and print `thirdeye stats`.
  3. Run both the exact repo-cwd population command and a broader 30-day command.
  4. If the population is empty, stop behavioral analysis, document zero-session evidence, and
     recommend enabling hooks for future runs.
- **Observed basis:** This review spent its useful effort discovering missing CLI/skill/data
  prerequisites rather than analyzing sessions.

## 5. Existing skill updates

Proposed changes for the existing thirdeye/session-review guidance:

- **Add a mandatory empty-population branch** before tool-mix analysis:
  - Run `thirdeye stats`.
  - Run the exact `--cwd` scan and a broad `--since` scan.
  - If both are empty, report instrumentation absence and skip session conclusions.
  - Why: avoids forcing fabricated top waste examples when no captured sessions exist.
- **Add CLI installation fallback** to `use-thirdeye`:
  - If `command -v thirdeye` fails, install or invoke the PyPI package `thrdi`.
  - Note that the executable may land in `~/.local/bin`.
  - Why: this environment had no `thirdeye` on `PATH`.
- **Add skill-location fallback** to the review workflow:
  - If `~/.cursor/skills/use-thirdeye/SKILL.md` is missing, check bundled package skills via
    `thirdeye skill list` or the package installation path.
  - Why: the bundled `use-thirdeye` reference was available only after installing `thrdi`.
- **Add tagging precondition**:
  - Only run `thirdeye tag <sid> 0 --add efficiency-review,<pattern>` after a unique session prefix
    is selected.
  - For empty populations, record "no sessions to tag" in the report.
  - Why: prevents noisy or failing tag attempts.

## 4. Skill recommendations

These are proposed only; no skill files were changed in this PR.

### New skill: `bootstrap-thirdeye-review`

- **Description trigger:** Use when an efficiency review asks for thirdeye but
  `thirdeye` is missing, skills are missing, or `thirdeye stats` reports zero sessions.
- **Workflow outline:**
  1. Check `command -v thirdeye`; if absent, install `thrdi` or report that the package is
     unavailable.
  2. Run `thirdeye skill list` and install bundled skills into a temporary path for
     reference if the requested skill paths are absent.
  3. Run `thirdeye stats` and both scoped and global `thirdeye list --json --since ...`
     scans.
  4. If the store is empty, produce a "no measured population" report instead of inventing
     session-level findings.
  5. Recommend hook setup for future sessions (`thirdeye add --cursor`, or the relevant
     platform) outside the PR unless explicitly requested.

### New skill: `workbench-session-selection`

- **Description trigger:** Use when reviewing `workbench` efficiency or any repository
  that launches nested `.workbench/<plan>/task-*` agent sessions.
- **Workflow outline:**
  1. Scan the configured repo path with `thirdeye list --json --cwd <repo> --since <date>`.
  2. Separately scan all sessions for `cwd` matching `/.workbench/.+/task-` under the
     configured repo, because task worktrees may not share the root cwd.
  3. Merge and de-duplicate candidate sessions by full session ID.
  4. Prioritize sessions from the last 7-30 days with 50+ events.
  5. Preserve the selected session prefixes in the report and tag event `0` after review.

## 6. Plan/convention changes

Proposed additions for `.workbench/conventions.md` or generated plan Context when using
workbench for multi-agent tasks:

- Include a short "repository map" in each plan Context: package roots, test commands,
  important config files, and the primary CLI entrypoints. This should reduce repeated
  filesystem exploration in task sessions once thirdeye capture is available.
- For each task, populate `Files:` with the smallest known set of relevant files and include
  relevant line ranges or symbol names in the task body. This directly targets the
  same-file re-read threshold (`Read >= 3x`) once measurable data exists.
- Add an explicit tool-selection convention:
  - Use dedicated search/read tools for code discovery.
  - Use shell commands for tests, package-manager operations, and git operations.
  - Avoid broad filesystem listing when a targeted glob/search is sufficient.
- For workbench-generated task prompts, include the original plan path and session branch
  near the top of Context so nested `.workbench/<plan>/task-*` sessions can be grouped
  reliably in later thirdeye reviews.
